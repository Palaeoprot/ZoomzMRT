## 1. Executive Summary & Purpose

Collaborators testing `ZoomzMRT` on archaeological and palaeoproteomic samples—specifically Frankie Tait and Dr. Geoff Smith (Project COEXIST, University of Reading)—have reported crucial operational bottlenecks and false-positive quality control flags when analyzing Waters SELECT SERIES MRT and MALDI-FTICR data:

1. **Format Friction:** The current `ZoomzMRT` pipeline only accepts `.mzML`, `.mzXML`, and Bruker `.d` formats. The Reading laboratory standardizes on Nick Michael's **MZSummer** pipeline, which co-adds multi-shot laser scans into **two-column tab-delimited `.txt` files** (and `_LMC.txt` lock-mass corrected files) or merged `.msd` (mMass spectrum data) files. Testers were forced into brittle external format conversions.
2. **False `BELOW_INTENSITY_THRESHOLD` Flags:** The current default marker definitions (`DEFAULT_COLLAGEN_MARKERS`) are human-centric and include non-deamidating peptides. When processing *Bos* (cattle) and *Capra* (goat/sheep) bone collagen samples, expected human peaks are missing or displaced, causing spots to report zero detected markers.
3. **Pervasive `C13_RATIO_ANOMALY` Flags:** The existing ¹³C₁ / *M*₀ isotopic validation checks the ratio `area_c13 / area_undeam`. In heavily deamidated archaeological collagen, the undeamidated monoisotopic peak (*M*₀) approaches zero, which causes the mathematical ratio to diverge and triggers false-positive failure flags across entire plates.
4. **Need for an Intuitive Visual Dashboard:** The command-line interface and flat CSV reports make plate-wide spot screening, replicate reconciliation, and spectrum interrogation cumbersome for laboratory analysts.

This Wayfinder lays out the exact technical blueprint to:
- Add native ingestion for two-column `.txt` / `.tsv` and `.msd` spectra.
- Import species-specific collagen marker dictionaries from **pSAGE** (*Bos*, *Capra*, *Ovis*, Cervidae, Equidae, Human).
- Reformulate the isotopic deamidation mathematics and intensity thresholds.
- Deploy a standalone, browser-based **Interactive QC & Deamidation Dashboard** tailored for plate-map exploration and replicate aggregation.

## 4. Algorithmic Fixes for Deamidation & QC Mathematics

### 4.1 Bounded Isotopic Validation (Replacing Fragile Division)
Currently:
```python
obs_c13_ratio = area_c13 / area_und
if abs(obs_c13_ratio - expected_c13_ratio) / expected_c13_ratio > 0.40:
    res.quality_flag = "C13_RATIO_ANOMALY"
```
When a sample is 90% deamidated, `area_und` is tiny (approaching zero). Random baseline noise in the undeamidated ¹³C₁ position divided by near-zero `area_und` creates huge numbers (> 2.0 vs theoretical ~0.60), falsely failing good deamidation data.

**Reformulation:**
1. Evaluate the ¹³C₁ ratio **only if** the undeamidated *M*₀ peak is well above the limit of quantitation (e.g. S/N >= 10 and undeamidated fraction >= 0.15).
2. For deamidated peaks, evaluate the ¹³C₁ isotope of the **deamidated envelope** (+1.9874 Da relative to *M*₀) against its theoretical expectation.
3. Replace the relative check with an envelope Pearson correlation or an absolute residual bound.

### 4.2 Centroid (Stick) vs Profile Peak Integration
MZSummer outputs profile or finely binned sticks, and `.msd` files contain both raw profiles and discrete peak lists.
- If data contains continuous profile points (> 5 points across the peak FWHM), apply background-subtracted trapezoidal integration (`integrate_peak`).
- If data consists of sparse centroid sticks, calculate deamidation directly using peak apex intensities (`measurement_method = "centroid_apex"`), skipping zero-area trapezoidal integration to prevent default fallbacks to `BELOW_INTENSITY_THRESHOLD`.

### 4.3 Lockmass Handling for Pre-Corrected Data
MZSummer optionally applies lockmass correction (`_LMC.txt`).
- Add `--precalibrated` / `--no-lockmass` mode.
- In `cli.py`, if filenames match `*_LMC*` or if the user specifies `--precalibrated`, bypass internal lockmass searching and accept the *m*/*z* axis as already calibrated.

## 5. Ingestion Architecture for `.txt`, `.tsv`, and `.msd`

### 5.1 Tab-Delimited Reader (`txt_reader.py`)
- Reads two-column whitespace/tab-delimited files directly using fast vectorised routines (`numpy.loadtxt` or `polars`).
- Detects header presence (`m/z`, `Intensity`) automatically.
- Extracts `sample_id` cleanly from filenames (e.g. `20260327MRT_KR71_0_K10_1.txt` -> spot `K10`).

### 5.2 mMass XML Reader (`msd_reader.py`)
- Parses `<mSD version="2.2">`.
- Decodes `<spectrum>` element containing zlib-compressed, base64-encoded little-endian IEEE 754 floats (`mzArray` and `intArray`).
- Reads `<peaklist>` elements when present, storing discrete centroids (`mz`, `intensity`, `sn`, `fwhm`).
